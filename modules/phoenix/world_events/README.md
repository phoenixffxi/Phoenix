# Phoenix World events

This C++ module feeds the Phoenix Admin Items and Monsters views. It uses existing
LandSandBoat module hooks and entity listeners; it adds no game database tables or
core source changes.

Set `WORLD_EVENTS_ENV` to `beta` or `prod`, `WORLD_EVENTS_AGENT_URL` to the local
box agent (for example `http://127.0.0.1:3100`), and `WORLD_EVENTS_AGENT_KEY` to
the agent's raw API key. Without all three, the module stays inactive. The box
agent forwards batches to Phoenix API using its separate `server:world` key.

- Monster `SPAWN`, `DEATH`, and `TREASUREPOOL` listeners record future spawns,
  kills, and rolled drops. Mobs already present when the module initializes do
  not get a synthetic spawn event.
- `OnPushPacket` observes inventory item quantity and slot changes. It nets
  movements for each character and item every time-server tick (2.4 seconds),
  so moving an item between the character's bags does not reset its obtained
  time. Existing inventory has no historical acquisition timestamp.
- Events are batched on a worker thread. The queue is capped at 20,000 events
  per map process. Network outages or a process exit can lose queued events;
  the module warns when the queue fills.

The collector sees treasure generated by the normal mob `DropItems` path. A
script that inserts into a treasure pool directly without triggering the mob's
`TREASUREPOOL` listener will not appear as a recorded drop.
